# 22 ноября 2026 — первая страница mouse.black

## Прямое поручение владельца

Домен mouse.black, существующая REG VM 151.248.113.177. Владелец настроил A-записи @ и www; публичный Google DNS подтвердил оба новых значения. Нужна простая страница HTML: только чёрно-белая палитра, переключатель инверсии, в центре родная мышь в норке с морганием, сильная русская фраза про локальность и пользовательский контроль, три загрузки с иконками Apple/Windows/Linux.

## Реализация

`website/`: buildless HTML/CSS/JS, без удалённых шрифтов, runtime-зависимостей, аналитики и рекламных трекеров. Родная пиксельная маска из `desktop/mouse/mouse-head.json`, отдельная группа глаз, норка по исходной геометрии бренда. Начальная тема тёмная; инверсия сохраняется локально; `prefers-reduced-motion` отключает анимацию. Три прямые ссылки работают без JavaScript.

Заголовок: «Твой компьютер. Твои правила.» Подпись: «Локальный браузер с тихим характером. Твоё пространство. Под твоим контролем.» Отсутствие аналитики явно относится к этому сайту; универсальная гарантия отсутствия слежки посещаемых сторонних сайтов не заявляется.

На момент проверки действующие feeds всех платформ показывают 6.0.36. Прямые DMG Apple Silicon / Windows x64 EXE / Linux x64 AppImage проверены анонимным HEAD (200, соответствующий размер). 6.0.37 не подставляется до действительной публикации. Все пакеты предварительные; Mac без нотариализации, Windows без цифровой подписи — это отражено в раскрываемой информации об установке.

## Размещение

Всё ведётся из OSMINOG с собственным `osminog-reg` и `OSMINOG_REG_SSH_KEY`. Новое окружение/ключи не создаются. Рабочая ветка сайта отдельная от браузерного релиза. `infra/website/deploy.sh` формирует проверенный архив статических файлов и метаданные точного коммита, затем публикует от osminog. Первичная подготовка — `/opt/osminog/website/releases/<sha>`; рабочий webroot после административной настройки — `/var/www/mouse.black/current`.

`infra/website/bootstrap.sh` — подготовленная однократная команда владельца/администратора. Проверяет собственный staged release, создаёт только Mouse webroot, `mouse.black.conf`, собственную директорию ACME `/etc/letsencrypt-mouse` и отдельный таймер продления. Конфигурация проходит `nginx -t` перед reload. Исходники АвтоЦены, её секреты, сервисы, каталоги и character backend не используются.

## Проверки и честный статус

Локальная проверка синтаксиса JS/Bash, HTML-ссылок и собственных assets; функциональная проверка упаковки с отклонением traversal/symlink/executable/checksum mismatch. Визуальная проверка в настоящем браузере: обе темы, сохранение инверсии после reload, мобильная вёрстка в viewport375. На узком экране подпись темы скрыта, доступная кнопка инверсии сохранена.

Публикация на mouse.black и доверенный HTTPS пока **не подтверждены**. Workflow сначала проверяет реальные полномочия osminog, сохраняет статический выпуск и сообщает `ADMIN_SETUP_REQUIRED`, если отдельный публичный webroot ещё не создан. Этот статус не означает готовый живой сайт. Если доступен существующий public webroot, workflow переключает только статические файлы и проверяет оба домена по HTTPS и SHA из release.json.

### Постоянная синхронизация будущих выпусков — подготовка

После подтверждения работающего домена владелец попросил выдавать новым посетителям текущий установщик, не заставляя их устанавливать старую версию и сразу обновлять её. Решение действует для всех будущих выпусков, а не только 6.0.37, и независимо по macOS arm64, Windows x64 и Linux x64.

Проверка реального канала публикации показала: исходные native workflows OSMINOG собирают кандидатов с `--publish never`; публикуют отдельные workflows OSMINOG-Releases, которые сначала проверяют публичные пакеты, затем двигают платформенные feeds. В текущих publisher workflows используется только собственный `github.token`; подтверждённого межрепозиторного dispatch-доступа нет. Поэтому вместо ложной привязки к сборке исходников выбран собственный server-side poll раз в 60 секунд после завершения предыдущего запуска, без новых секретов и без изменения browser release workflows. Это ограниченная задержка обнаружения плюс время переноса и проверки файла, не обещание мгновенного webhook.

Три авторитетных канала: `channels/mouse/macos-arm64.json`, `platforms/windows/mouse-x64/latest.json`, `platforms/linux/mouse-x64/latest.json` в main собственного OSMINOG-Releases. Resolver требует точные platform/arch/version/tag/filename/URL, publishedAt и совпадение размера/SHA256 с опубликованным asset. Preview/prerelease допустим, draft и незавершённый файл нет. API release читается только для новой версии; обычная минутная проверка не скачивает и не хеширует заново 400 MB. Устаревший feed не понижает версию; изменённые байты под прежним именем запрещены. Неисправная платформа сохраняет предыдущий рабочий установщик, другие могут обновиться.

Новый runtime работает только под существующим osminog в `/opt/osminog/website/automation`, собственные user units `mouse-website-sync.service` и `.timer`. Ограничения: 192 MiB RAM, 25% одного CPU, 16 задач, 20 минут на запуск; общего root/system service изменения нет. Source bundle содержит только проверенные скрипты и статику, а каталог 72 переводов экспортируется на CI; серверу для построения сайта нужен только Python.

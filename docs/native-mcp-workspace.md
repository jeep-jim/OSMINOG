# OSMINOG: один разговор через инструменты MCP

Статус: реализация локального моста; подключение настоящего ChatGPT ещё не выполнено. Не объявлять исходную задачу завершённой по fixture-тестам.

## Что изменено

В настройках подключения добавлен локальный мост текущего проекта. Он работает только на 127.0.0.1 с непредсказуемым приватным адресом, отвергает запросы браузерных Origin и чужой Host. Адрес меняется при включении. Не публикуйте его и не отправляйте в чат. Туннель должен запускаться на том же компьютере, где работает OSMINOG. Сервер не открывает входящий порт в интернете.

Инструменты: workspace_read (свежий контекст и токен холста), browser_read (DOM, изображение и токен), browser_act (одноразовый снимок и нативное действие), canvas_apply (проверка точного состояния холста). Проект закрепляется при включении; переключение проекта блокирует команды. Пока включён MCP, page:user-send не запускает вторую модель только для выбранного провайдера в подключённом проекте; остальные провайдеры сохраняют прежнее поведение. MCP не вызывает модель, не редактирует пользовательские сообщения и не подменяет ответы сайта.

## Подключение и границы

Обычный chatgpt.com должен подключить мост как инструмент. Сам по себе локальный объект BrowserContext этого не делает. Поддерживаемый путь OpenAI: private Secure MCP Tunnel + custom MCP plugin. Требуются tunnel_id, локально настроенный runtime API key для tunnel-client и права соответствующего аккаунта. Не вводить секреты в переписку и не сохранять в репозитории. Это отдельная настройка аккаунта и компьютера, не часть входа в ChatGPT.

1. Открыть «Подключение ИИ», выбрать сервис и подготовить подключение для нужного проекта; скопировать приватный адрес в локальную конфигурацию tunnel-client.
2. На этом же ПК настроить и запустить официальный tunnel-client, связанный с нужным аккаунтом/рабочим пространством. Проверить doctor/readiness.
3. Добавить custom MCP server в ChatGPT Plugins с Connection: Tunnel; установить и выбрать плагин в разговоре.
4. Из этого разговора прочитать текущую страницу, создать красный круг и проверить фактический объект. Ответы должны быть в исходной беседе, без второго запроса исполнителя.

Не выдавать localhost-адрес за публичный URL. Не утверждать поддержку MCP в обычном веб-чате DeepSeek без отдельной подтверждённой интеграции. Требование «любой ИИ без настройки» этим выпуском не выполнено. Не отключать подтверждения самого сервиса в обход его настроек.

Официальные источники (проверены 15.10.2026):
- https://developers.openai.com/api/docs/guides/custom-mcp-server
- https://developers.openai.com/api/docs/guides/secure-mcp-tunnels
- https://modelcontextprotocol.io/specification/2025-03-26/basic/transports

Мост реализует JSON-RPC initialize/ping/tools/list/tools/call и уведомления через Streamable HTTP с JSON-ответами; GET возвращает 405. Совместимость живого ChatGPT необходимо проверить после настройки туннеля.

## Состояние подключения и другие сервисы

В панели ИИ отображается «доступ диалога не подтверждён». Сервер не умеет достоверно связывать входящий MCP-запрос с конкретной открытой беседой, поэтому зелёного индикатора для неё нет. В окне подключения отдельно отображаются выключенное состояние, ожидание запроса, время успешного workspace_read, ошибка инструмента и смена проекта. Сам запуск сервера и initialize не подтверждают чтение. История чтения очищается при отключении; при смене проекта не показывается как актуальная.

Gemini: официальная справка https://support.google.com/gemini/answer/17209137 описывает custom apps в Connected Apps. Это подтверждает существование механизма, но не совместимость нашего локального сервера с аккаунтом пользователя. Для Gemini нужен доступный сервису endpoint и подходящая авторизация; OpenAI Secure Tunnel не является общим решением для Google. Инструкция доступна из окна подключения.

DeepSeek: подключение инструментов к исходному веб-чату не реализовано; кнопка подготовки для него отключена с объяснением. API tool calling не означает поддержку инструментов в chat.deepseek.com. Claude также не проверен end-to-end. Нельзя выдавать эти ограничения за исправленные или выпускать обновление с обещанием, что все веб-чаты уже видят рабочее пространство.

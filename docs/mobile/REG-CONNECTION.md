# Подключение OSMINOG к REG

Только `jeep-jim/OSMINOG`, environment `osminog-reg`:
https://github.com/jeep-jim/OSMINOG/settings/environments

## Что вносит владелец / администратор

| Тип | Имя | Содержимое |
| --- | --- | --- |
| Secret | OSMINOG_REG_AI_API_KEY | Отдельный API-ключ ИИ REG для OSMINOG |
| Variable | OSMINOG_REG_AI_BASE_URL | Точный base URL из инструкции выбранной модели |
| Variable | OSMINOG_REG_AI_HOST | Точный hostname этого URL |
| Variable | OSMINOG_REG_AI_MODEL | Точный model ID из инструкции |
| Secret | OSMINOG_REG_SSH_KEY | Приватный SSH-ключ отдельного ограниченного пользователя OSMINOG |
| Variable | OSMINOG_REG_SSH_USER | Имя пользователя osminog или osminog-* / osminog_* |
| Variable | OSMINOG_OCEAN_URL | HTTPS URL собственного сервиса после его установки и проверки |

API-параметры без ключа можно прислать из REG → выбранная модель → «Инструкция для API». Сам ключ вводится в GitHub Secret, не в чат, Git или APK. API-ключ не заменяет SSH-ключ. Не копировать доступы АвтоЦены. Существующая отдельная read-only проверка проверяет разрешённый REG-хост и `/opt/osminog`; наличие VM само по себе не даёт приложению доступа.

После внесения: запустить `OSMINOG connection configuration readiness` и `OSMINOG REG — isolated access check` в Actions OSMINOG. Первый выводит только наличие параметров, второй не устанавливает приложение. Ни один не подключает модель автоматически.

## Что делает разработчик после доступа

1. Проверяет доступ отдельного пользователя и ресурсы собственной части хоста.
2. Завершает сервис ретрансляции под требование хранения личного содержимого/медиа на устройствах. Старый SQLite pilot не выкатывает как соответствующий этому контракту.
3. Доставляет API-конфигурацию в отдельный процесс OSMINOG; ключ только на сервере, не в клиенте. Сверяет реальный API-протокол и делает ограниченный синтетический вызов.
4. Проверяет реальный обмен двух устройств, отзыв мысли и отключение поиска. Отдельно проверяет передачу модели только разрешённого пользователем содержимого.
5. Подключает личный разговор, память и самостоятельный поиск персонажа отдельными этапами. Нынешний REG-адаптер ранжирования из PR #105 их не реализует.

Google/Telegram client IDs понадобятся для соответствующего способа входа; это отдельная конфигурация, не условие первого синтетического вызова REG. Значения и успешность регистрации сейчас не подтверждены.

# Сессии исполнения чата — Windows 4.0.12

## Включение

В шапке Осьминога нажмите «Автопилот: выкл». Переключатель включает безопасные действия **для новых задач текущего проекта до закрытия приложения**. По умолчанию выключен. Уже запущенная задача сохраняет настройку, с которой началась. «Стоп ИИ» отменяет активные задачи. Публикация и неизвестные кнопки требуют отдельного подтверждения; распознанные пароли, токены, платежи и удаление блокируются. DOM-классификация эвристическая.

## Путь сообщения

`page:user-send → OriginalActions → Orchestrator → AgentTools/Control → observation → provider feedback → next model turn`.

Это интеграция существующего отдельного служебного исполнителя. Она не добавляет нативные инструменты непосредственно облачной модели в исходном диалоге провайдера. Работа живых аккаунтов не подтверждается fixture-тестами.

`osminog.chat.actions` доступен только доверенному главному renderer приложения через `OSMINOGNative.chatActions`. Произвольные страницы не получают этот метод. Сессия создаётся main-процессом при принятом пользовательском сообщении и привязана к проекту, исходной вкладке, времени жизни и отзыву доступа.

```js
await OSMINOGNative.chatActions({
  sessionId, // существующая активная сессия main-процесса
  actions: [{ tool: 'browser_act', args: {
    id: tabId, snapshot, actions: [{ type: 'click', x: 100, y: 100 }]
  }}]
});
// {ok, results: [{action, result}], nextSnapshot}
```

Поддерживаются browser_read, browser_act, browser_context, openTab и switchTab. Для raw click/type/key/scroll/drag нужны id и snapshot. browser_act принимает одно действие; новый snapshot возвращается в observation. Координаты относятся к viewport вкладки. Не переиспользуйте старый snapshot. Очередь останавливается на первом `ok:false`; новый план — отдельный вызов в той же активной сессии.

## Прогресс и журнал

Статус рядом с последним распознанным пользовательским сообщением (при неизвестной разметке — в углу чата). Внизу оболочки — сокращённый sessionId и таймер. Статусы: обдумывание, шаг N/M, готово, ошибка, остановлено, действий нет. M — число уже поступивших действий, не предсказание будущих шагов модели.

Журнал: `<Electron userData>/logs/orchestrator.log`. На Windows точный userData зависит от установленной конфигурации приложения. JSONL содержит timestamp, sessionId, action, result, duration и error-code. Значения полей, текст сообщений, cookies, секреты и снимки в журнал не записываются. Стек исключения возвращается в результат технической ошибки, но не пишется в журнал вместе с возможными приватными значениями.

## Добавление действия

1. Добавьте проверку аргументов и маршрутизацию в main.cjs/OriginalActions.
2. Включите тип в parsePlan и реализуйте нативный ввод в Control, если нужен новый вид ввода.
3. Добавьте проверку живой цели в action-policy.cjs; неизвестные цели требуют подтверждения.
4. Верните ok/error и наблюдение после действия. Проверьте отзыв доступа и остановку.
5. Дополните unit-тесты и orchestrator-smoke.cjs.

## Коррекция ответа исполнителя (кандидат 4.0.13)

Для execution используется отдельная инструкция команд вместо общей разговорной. Если первый ответ — только текст, хост один раз просит машинную команду; неверная схема допускает максимум две коррекции. В журнале код EXECUTOR_FORMAT_INVALID, без текста ответа пользователя. После неудачного инструмента остаток calls не выполняется, ошибка возвращается модели для нового плана.

Дополнительно принимается сырой или fenced JSON `{ "id": "tab-id", "snapshot": "issued-token", "actions": [{ "type": "click", "x": 100, "y": 100 }] }`. Только один action на свежий snapshot; последовательность выполняется через повторные ходы с наблюдением. Угадывание snapshot запрещено. waitFor не поддержан. `{ "actions": [] }` завершает цикл без дополнительного запроса формата.

API-ключ и включение платного tools API не нужны. Это исправление существующего служебного исполнителя, не подключение native function calling к оригинальному веб-диалогу. Прогон 115 unit-тестов не подтверждает работу живого аккаунта и не является логом шести пользовательских сценариев.

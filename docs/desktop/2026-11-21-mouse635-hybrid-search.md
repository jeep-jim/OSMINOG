# Mouse Browser 6.0.35 — публичные SearXNG и YaCy

## Текущее решение владельца

21 ноября 2026 владелец прямо выбрал гибрид: основной поиск через публичные SearXNG, бесплатно и без ключей; если они недоступны — YaCy, когда пользователь готов ждать дольше. Это заменяет прежнюю основную цепочку Brave / DuckDuckGo / Mwmbl / MyMemory в текущем кандидате. Уже сделанные Agent Chat, переносы кнопок, закрепление окон и стабильные списки файлов сохраняются. Собственный сервер, Docker и HTML scraping не добавляются.

Статус: изменения готовятся в source PR [187](https://github.com/jeep-jim/OSMINOG/pull/187). Публикация 6.0.35 ещё не подтверждена. Release PR [63](https://github.com/jeep-jim/OSMINOG-Releases/pull/63) остаётся черновиком с тремя `ready:false` и без `PUBLISH_OWNER`.

## Реализуемое поведение

Основной маршрут проверяет до трёх публичных HTTPS API SearXNG в общем бюджете 24 секунды, с пределом 7 секунд для одного узла. Успешная пустая выдача остаётся пустой; она не считается падением сервиса. Исходный запрос сохраняется; основной маршрут SearXNG не использует перевод и прежнюю поисковую цепочку.

При отказе основного маршрута чат поиска показывает предложение «Продолжить через YaCy» и срок до 45 секунд. Запрос отправляется резервному сервису только после отдельного нажатия. Одноразовое разрешение связано с исходными query/filter/requestId, действует не более двух минут и потребляется один раз. Новый запрос, другой фильтр, обычный повтор, отказ, Stop и закрытие сбрасывают предложение. YaCy проверяет до двух публичных HTTPS-узлов в общем бюджете 45 секунд; один узел получает не более 20 секунд. Пагинация относится к уже выбранному и разрешённому источнику.

В UI убрана форма запроса Brave API-ключа. Вместо неё сворачиваемое объяснение основной и резервной схемы. Ранее сохранённые ключи и совместимые служебные API не удаляются, но они не должны менять новый основной маршрут. В состоянии YaCy видны источник, увеличенное ожидание и Stop. Технические ошибки транспорта не выводятся пользователю сырым стеком.

Для допустимого короткого русского запроса предложение YaCy дополнено отдельным, изначально выключенным флажком «Разрешить перевод через MyMemory, если результатов нет». Согласие прямо раскрывает передачу текста сервису перевода. Только при этом дополнительном выборе и отсутствии тематических результатов исходного YaCy-запроса разрешён GET MyMemory `/get` (до500 UTF-8 bytes, до6 секунд); полученный перевод отправляется тому же YaCy. Это входит в общий45-секундный бюджет, не создаёт отдельной прежней поисковой цепочки. В UI сохраняется исходный запрос, а фактический перевод раскрывается в заметке источника. Без флажка перевод запрещён.

## Проверяемые внешние контракты

- [Официальный Search API SearXNG](https://docs.searxng.org/dev/search_api.html): GET/POST `/search`, `q`, `format=json`; неподключённый формат отвечает 403. Документация прямо указывает, что у многих публичных серверов JSON отключён.
- [Официальный список публичных SearXNG](https://searx.space/) и его `data/instances.json`: наличие сервера в каталоге не доказывает доступность JSON для клиента.
- [Официальная спецификация MyMemory GET](https://mymemory.translated.net/doc/spec.php) и [лимиты](https://mymemory.translated.net/doc/usagelimits.php): UTF-8 `q` до500bytes, `langpair`, необязательный ключ; анонимный бесплатный лимит5000символов в день. Используется только `/get`, без `/set`, загрузки памяти, email или ключа.
- [Официальный адаптер YaCy в SearXNG](https://docs.searxng.org/dev/engines/online/yacy.html): публичные HTTPS peers и глобальный режим.
- [Документация YaCy Search API](https://wiki.yacy.net/index.php/Dev:APIyacysearch): `/yacysearch.json`, `query`, `resource=global`, `startRecord`, `maximumRecords`, `contentdom=text`. Wiki относится к старой документации; актуальный контракт дополнительно проверяется по реальным ответам.

## Сетевая граница и приёмка

В предварительной проверке из текущего рабочего окружения `https://search.rhscz.eu/search` и `https://search.utilibre.org/search` вернули HTTP 429 с текстом `Too Many Requests` на точный запрос «новости про антропик». YaCy `https://yacy.searchlab.eu/yacysearch.json` не ответил и при отдельной попытке с 45-секундным сетевым ожиданием. Эти наблюдения не доказывают отказ для всех сетей или пользователей и не считаются успешно работающим поиском.

Функциональная приёмка отделяет корректный отказ и согласие от реальной способности найти сайты. Для публикации нужны настоящие тематические URL по исходному запросу владельца, полученные через production preload / Chromium transport, с исходными JSON bytes, SHA-256 и связью каждого результата с ответом API. Собственная HTTP-фикстура может подтвердить UI, но не доступность публичной сети. Три корректно обработанных отказа не заменяют этот критерий.

Локальная проверка UI после реализации offer lifetime: `mouse-search-ui.test.cjs` — 23/23 PASS, включая одноразовое разрешение, запрос/фильтр, срок действия, сброс и замену токена. Полная backend и установленная приёмка нового гибрида ещё предстоят.

### Дополнительная проверка публичного YaCy

Публичный оператор [yacy.space](https://yacy.space/) отвечает на `/yacysearch.json`: точный исходный русский запрос дал HTTP200, `application/json`, 2745 bytes, SHA-256 `34ef48d9d62edb4d01edcb9629308760c67a75b68f63787812c7d70f9b918dc8`, 10 URL за 8907 ms. Поле `searchTerms` сохранило исходный запрос. Однако все десять заголовков/URL относились к общим новостям, городам, анекдотам и консалтингу; совпадений с `anthropic` / `антропик` не было. Это подтверждает доступный JSON API, но не выполнение исходной поисковой задачи. Такие строки не должны объявляться тематическим успехом.

### Проверенный второй узел и основание для добровольного перевода

`https://search.joestr.at/yacysearch.json` дал HTTP200 JSON на оба независимых запроса: русский исходный — 52485 bytes, SHA-256 `bdc87cfac44b6bca8f3626ab926bd0d770ff4276af266d1e7a1e87722e394327`, 11020 ms, 0/10 тематических строк; английский контроль `news about anthropic` — 33663 bytes, SHA-256 `1a9544475b78bcc98a0eb698b651595b3c8508cdecd1fec9cdfc608b4ecc9c97`, 9518 ms, 4/10 строк с Anthropic в URL/названии/описании. Это страницы тем kottke.org, TNW, The Verge и WirtschaftsWoche; свежесть новостей не проверялась. Root сверил оба hash с raw bytes. Поле `searchTerms` у этого узла содержит form-encoded пробелы (`+`), что учитывается при строгой проверке эха запроса без изменения outbound query.

Английский контроль — отдельный запрос исследователя, не доказательство автоматического перевода или успешного исходного русского поиска. Он послужил основанием добавить отдельный добровольный перевод внутри согласованного YaCy. Полная цепочка должна быть подтверждена установленной сборкой: исходный русский ответ, явный флажок, фактический MyMemory JSON, дословный поисковый перевод и реальные тематические URL. До этого capability остаётся неподтверждённой.


## Заменено следующим прямым решением владельца

Гибрид выше не публикуется. Владелец выбрал обычный поисковик из общей настройки браузера и собственное отображение его настоящей выдачи плитками. SearXNG/YaCy/MyMemory больше не являются планом runtime. Записи и исходные проверки оставлены как история; актуальное ТЗ и Mac-only выпуск — [выбранный поисковик](2026-11-21-mouse635-selected-engine.md).

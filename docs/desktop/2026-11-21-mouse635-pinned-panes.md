# Mouse 6.0.35 — закрепление окон и системное меню раскладок

Прямое дополнение владельца к выпуску от 2026-11-21: пункт «Закрепить окно» по правой кнопке с канцелярской кнопкой, сохранение настроенного вида окна, выбор схемы через системное меню «Окна» с отметкой фактической схемы текущего стола. Статус этой записи: **исходники и локальные проверки готовы; установленная приёмка и публикация ещё не подтверждены**.

## Реализованный контракт

- Контекстное меню закрепляет конкретное окно вместе с его вкладкой. На закреплённом окне видна кнопка открепления. Повторный пункт меню называется «Открепить окно».
- Закрепление сохраняет привязку вкладки и цепочку родительских разделителей: направление, долю и сторону. Нельзя закрыть/подменить/перенести закреплённую вкладку, разделить само окно, изменить его границы перетаскиванием, применением схемы или восстановлением истории.
- Свободное соседнее поддерево можно менять, если границы закреплённого окна остаются прежними. Обычная навигация, перезагрузка сайта, временное разворачивание окна и порядок вкладок в верхней полосе сохраняются.
- Если активное окно закреплено, новая или выбранная скрытая вкладка размещается в свободном окне. Если свободных окон нет, интерфейс просит сначала открепить окно. Закреплённое пустое окно остаётся пустым.
- `pinnedPanes` — необязательное поле раскладки каждого стола. Старые профили без закреплений сохраняют прежнюю форму данных. Приватный режим использует собственный `MemoryStore`; его закрепления не переносятся в обычный профиль. Undo/Redo не снимает закрепление: для этого нужна явная команда.
- Проверки выполняются в renderer и в `mouse-desktops.cjs`; прямой вызов close/move/save/apply-mode через штатный IPC также проверяет закрепление. `mouse-main.cjs` сохраняет поле через обычный whitelist настроек.
- Меню «Окна» использует настоящий `Electron.Menu`, показывает миниатюры схем и отмечает точное текущее дерево. Два окна рядом и друг над другом различаются. Изменённые пропорции считаются пользовательской схемой. Footer сохраняет порядок видимых вкладок; контекстная схема сохраняет выбранную правой кнопкой вкладку первой.
- Native payload содержит desktop ID и исходную привязку окна. Renderer отклоняет устаревшие команды после смены стола, перемещения вкладки и заполнения прежде пустого окна, включая промежуток ожидания выхода из fullscreen.

Основные файлы: `desktop/mouse/layout.js`, `desktop/mouse-desktops.cjs`, `desktop/mouse-context-menu.cjs`, `desktop/mouse/context-menu.js`, `desktop/mouse/browser.js`, `desktop/mouse/mouse-613-ui.js`, `desktop/mouse/pane-pins.css`.

## Проверки и оставшийся выпускной gate

Локальные проверки покрывают сохранение/повторное чтение старого профиля, отдельные столы и приватный bank, блокировку закрытия и переноса через настоящий host handler, атомарный отказ истории, разрешённые изменения свободного соседнего поддерева и устаревшие context payloads. Полный source suite после интеграции: **1130 tests, 1124 PASS, 0 FAIL, 6 Windows-only SKIP**. Путь к журналу в рабочем окружении: `mouse635-final-unit.log`; SHA-256 сообщён root-проверкой: `cdaf1a449242fb383adc05a5af66981909fa191e9a2769d1c5d93a293d305b47`. Этот результат не заменяет установленную приёмку.

Добавлен `desktop/mouse-635-layout-smoke.cjs` в `--mouse-635-smoke`, этап `pinned-panes` после Agent chat. Он использует две собственные HTTP-страницы в настоящих native views, реальные OS-ввод и клавиши системного меню, запись проверенных пунктов меню, чтение размеров и идентичности страниц, повторное чтение сохранённых данных, переход между столами и полный вход/выход из приватного режима. Снимки через `globalCapture.acquire(display)`: `mouse-635-layout-native-menu.png` и `mouse-635-pane-pinned.png`, оба с оригинальным полным кадром дисплея. Успех отмечается `MOUSE_635_PINNED_PANES_PASS` и полями `facts.panes`; исходные результаты хранятся рядом с булевыми проверками.

Legacy native smoke меню и стартовой страницы обновлены под новый реальный native popup. Проверки разрешений, живых страниц, cookies, fullscreen и modal barrier сохранены. Native smoke здесь ещё не выполнялся; результаты Mac arm64, Windows x64 и Linux x64 должны быть приняты по точному исходному SHA и пакетам до публикации.

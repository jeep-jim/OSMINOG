# Mouse 6.0.25 — локальное открытие и редактирование документов

Дата сверки: 2026-11-18. Статус: реализация и локальные проверки; установленная macOS arm64-сборка 6.0.25 ещё не проверена. Этот документ не подтверждает публикацию DMG или переключение канала обновления.

## Требование и размещение в Mouse

Поручение владельца: открывать PDF, Word и Excel внутри Mouse, с доступными правками и сохранением. Реализация использует отдельное окно редактора внутри оболочки браузера, список открытых документов и существующий механизм перекрытия native web views. Входы — кнопка «Документы» и «Файл → Открыть документ…» (`⌘O`). Сетка браузера остаётся отдельной от вкладок документов; документы не превращаются в обычные HTTP-вкладки. Исходники интеграции: [documents.js](../../desktop/mouse/documents.js), [browser.js](../../desktop/mouse/browser.js), [mouse-main.cjs](../../desktop/mouse-main.cjs), [mouse-preload.cjs](../../desktop/mouse-preload.cjs).

Закрытие крестиком шапки сворачивает редактор; открытые документы и правки остаются в памяти. Отдельный крестик документа закрывает этот документ с выбором сохранения при наличии правок. `⌘S` сохраняет активный документ, `⌘⇧S` открывает «Сохранить как…». При открытом редакторе `⌘W` направлен на активный документ. Эти связи реализованы в исходниках; проверка настоящих клавиш и окон установленного приложения остаётся частью native gate.

### PDF: способ внесения правок

PDF.js отрисовывает текущую страницу в canvas; отдельный canvas показывает новые отметки. При смене страницы/масштаба предыдущая задача рендеринга отменяется, использованная страница освобождается через `cleanup()`. При закрытии редактора задача PDF.js уничтожается. Это сокращает удержание отрисованных страниц, но не является гарантией фиксированного расхода памяти: в памяти также находятся исходные байты, структуры PDF.js, canvas и данные экспорта.

Оболочка открывается через `file:`, чей URL origin для PDF.js равен `null`. В закреплённой версии 4.10.38 библиотека поэтому создаёт `blob:` module-worker wrapper, импортирующий локальный `pdf.worker.mjs`. В CSP разрешён `worker-src 'self' blob:`; `script-src 'self'` остаётся без `unsafe-eval`, remote worker URL и PDF scripting manager не добавлены. До этой точечной корректировки политика `worker-src 'self'` не разрешала создаваемый библиотекой blob worker, что допускало переход PDF.js к main-thread fallback. Native helper теперь требует `pdf.workerOffMainThread === true`: проверяет `loadingTask._worker.port instanceof Worker` при первом открытии, чтении сохранённого PDF и повторном открытии. Для UI-проверки adapter выставляет диагностический атрибут только при `MouseNative.test`. Это ожидаемый native gate; его успешный запуск ещё не зафиксирован.

При сохранении pdf-lib добавляет текст и графику в PDF без растеризации всех страниц. Отметки здесь — добавленные текстовые и графические команды; полноценный обмен редактируемыми PDF comments/annotation objects не заявлен. Исходное содержимое под отметкой сохраняется. Закрашивание не удаляет скрытый текст и не является redaction. Для добавленного текста используется DejaVu Sans; покрытие символов ограничено этим шрифтом. Зашифрованные/парольные документы и специальные PDF-конструкции не получают обещания совместимого редактирования.

Если правок и дополнительных поворотов нет, экспорт возвращает исходные байты. После успешного сохранения редактор заново открывает сохранённые данные, чтобы старые RAM-отметки не накладывались повторно. Позиция страницы, масштаб и инструмент передаются через `getView()`.

### Word: сохранение существующей структуры

Редактор изменяет отдельные `w:t` и свойства `w:rPr`, сохраняет `w:pPr`, остальные run properties, XML-атрибуты и неизвестные узлы. Значимые пробелы сохраняются через `xml:space`. Правка текста не заменяет весь документ плоским HTML. Экспортируются только изменённые `word/document.xml`, `word/header*.xml` и `word/footer*.xml`.

Отображение в Mouse может отличаться от Word: доступные наследуемые стили применяются частично, нумерация отображается упрощённо, сложные объекты могут быть скрыты или заменены подписью. Непоказанные части не удаляются из исходного пакета. Вставляемый текст обрабатывается как текст; внешние ссылки изображений не загружаются этим редактором. Изображения для просмотра ограничены встроенными PNG/JPEG/GIF/WebP, отобранными native codec по сигнатуре.

### Excel: расчёт и состояние сохранённых результатов

Встроенный интерпретатор поддерживает арифметику, проценты, сравнения, объединение строк, относительные/абсолютные ссылки, ссылки между листами, прямоугольные диапазоны и `SUM`, `AVERAGE`, `MIN`, `MAX`, `COUNT`, `IF`, `ROUND`. Формулы вводятся с английскими именами функций и запятыми между аргументами. Числовой ввод использует точку как десятичный разделитель; апостроф перед значением позволяет сохранить числоподобную строку текстом.

Интерпретатор не использует JavaScript `eval`, не загружает внешние книги и не подставляет cached `<v>` вместо результата поддерживаемой формулы. Есть ограничения размера выражения, глубины, диапазона и вычислительной работы; циклы и превышение лимита дают явное состояние ошибки/неподдерживаемого расчёта. Именованные диапазоны, structured references, внешние ссылки и неподдерживаемые функции не считаются пересчитанными.

Состояния ячеек различаются в DOM и UI: `calculated` — вычислено в Mouse; `cached` — результат из исходного файла; `stale` — сохранённый результат после правок, который здесь не пересчитан; `pending` — ещё ожидает расчёта; `error` — ошибка. Старый результат помечается и после изменения книги отображается зачёркнутым. Сложные форматы чисел сохраняются в XML, даже если экран показывает значение упрощённо.

Новый текст записывается через `inlineStr`, без изменения общей записи `sharedStrings` у других ячеек. Стиль `s` и неизвестные свойства ячейки сохраняются. При правке формулы её старое cached value удаляется; экспорт не придумывает новые значения неподдерживаемым формулам. В `xl/workbook.xml` выставляются `fullCalcOnLoad` и `forceFullCalc`. Неизменённые формулы и их существующий кеш в других ячейках сохраняются; другие программы должны выполнить пересчёт, а не полагаться на старый кеш.

При реальном изменении XLSX доверенный [codec.save](../../desktop/mouse-document-zip.cjs) удаляет старый `xl/calcChain.xml` и только относящиеся к нему relationship/content-type. Renderer не получает интерфейс произвольного удаления ZIP-частей. Необычный target цепочки отклоняется. Microsoft описывает calculation chain как необязательный порядок вычисления, а не дерево зависимостей: [Working with the calculation chain](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-the-calculation-chain). Формула и cached value — разные элементы: [Working with formulas](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-formulas).

## Сохранение, конфликт и приватный режим

[DocumentService](../../desktop/mouse-documents.cjs) хранит пути только в main process; renderer получает непрозрачный ID, имя, тип, размер, ревизию и содержимое выбранного файла. IPC проходит проверку доверенного shell frame. Обычным веб-страницам capability открытия/чтения/сохранения локальных документов не добавлена.

Первое «Сохранить копию» открывает системный Save dialog и предлагает имя с суффиксом «— копия». Исходник не меняется до явного выбора места записи. Пользователь может явно выбрать исходный путь и подтвердить замену; повторное «Сохранить» работает с выбранной сохранённой копией. «Сохранить как…» снова требует системного выбора пути. Расширение должно соответствовать открытому формату. Отмена диалога сохраняет документ и его dirty state в редакторе.

Перед записью проверяются ID текущей записи, privacy epoch, ревизия и поколение правок. Новые правки, закрытие документа или смена режима во время диалога делают старый payload неактуальным. SHA-256 исходника/последней сохранённой копии сравнивается с диском; при обнаруженном внешнем изменении перезапись отклоняется с предложением сохранить новую копию. Запись идёт через эксклюзивно созданный временный файл в той же папке, `fsync`, повторную проверку состояния и синхронную точку commit: `renameSync` и обновление ревизии/хэша без передачи управления между ними. Directory fsync выполняется после commit с гарантированным закрытием handle. Временный файл очищается при ошибке. Это проверки обнаруженных конфликтов, а не межпроцессная блокировка чужих редакторов.

Нативное открытие разрешено только через системный picker: выбранный путь разрешается через `realpath`, читается обычный файл с проверкой размера. При записи существующая символическая ссылка в качестве целевого файла отклоняется. Renderer не выбирает произвольный путь строкой IPC.

Правки и черновики живут в памяти процесса; отдельного восстановления после аварии/перезапуска из дискового autosave нет. Dirty state устанавливается при вводе, содержимое собирается перед переключением/сохранением и отложенно для RAM draft. Закрытие документа, выход из приложения и переход между обычным/приватным режимом предусматривают выбор «Сохранить / Не сохранять / Отмена». Отмена оставляет приложение и документы открытыми. Решения «Не сохранять» при общем выходе применяются после решения по всем документам и повторной проверки поколений правок, чтобы последующая отмена или новая правка не уничтожили их черновики. Повторный полный draft с тем же содержимым не считается новым изменением; устаревшая expectedRevision отклоняется.

После принятого перехода приватности открытые document records очищаются и старые ID больше не используются. Явно сохранённый из приватного режима файл остаётся на Mac; это отражено в заголовке Save dialog. Приватный режим не означает автоматического удаления уже сохранённых файлов. Источники: [mouse-main.cjs](../../desktop/mouse-main.cjs), [mouse-private.cjs](../../desktop/mouse-private.cjs), [mouse-lifecycle.cjs](../../desktop/mouse-lifecycle.cjs).

## Ресурсные пределы

Пределы относятся к конкретным операциям и структурам, не к общему RAM-потреблению приложения. В таблице MiB = 1 048 576 байт; длины JS-строк считаются как `String.length`.

| --- | --- |
| Открытый/сохраняемый файл | 32 MiB |
| Открытые документы | 6 |
| Проверка суммы байтов документов при открытии следующего файла | 96 MiB |
| RAM draft одного документа | 2 × 1024 × 1024 единиц длины сериализованной JSON-строки |
| OOXML ZIP | 4096 entries; путь до 1024 байт; распакованная часть до 32 MiB; суммарно до 128 MiB |
| XML части OOXML | До 8 MiB каждая; до 24 MiB суммарно для отбираемых XML частей |
| Встроенные растровые изображения для просмотра | До 8 MiB одно; до 32 MiB суммарно; до 16 000 000 пикселей одного и 32 000 000 суммарно |
| Word preview | 8000 учитываемых узлов, 1200 абзацев, 1000 ячеек таблиц, 150 изображений, 1 000 000 единиц текстовой длины |
| XLSX модель / отображение | 100 листов, 100 000 ячеек; видимый блок 30 × 16 ячеек |
| Формулы | 4096 единиц длины, 2048 токенов, глубина 64; диапазон до 10 000 ячеек и отдельный бюджет вычислительной работы 10 000 |

ZIP codec проверяет структуру central/local records, CRC, наложение областей, коллизии и обход пути; зашифрованные ZIP, ZIP64, макросы и XML DTD/entities отклоняются. Неизменённые ZIP local records, compressed payload и соответствующие данные частей сохраняются. Это не обещание побайтово неизменного всего архива после правок: центральные смещения и изменённые XML части пересобираются. ## PDF runtime и проверенные advisory

Используются неизменённые копии ранее включённых в репозиторий `vendor/pdf` файлов. PDF.js содержит версию **4.10.38**, build **f9bea397f**. Локальные SHA-256, источники и лицензии всех **9 файлов** — 5 runtime assets и 4 notices — перечислены в [document-vendor/README.md](../../desktop/mouse/document-vendor/README.md).

На 2026-11-18 сверены две официальные страницы Mozilla:

- [GHSA-wgrm-67xf-hhpq](https://github.com/mozilla/pdf.js/security/advisories/GHSA-wgrm-67xf-hhpq): affected `<= 4.1.392`, исправление `4.2.67`; advisory также описывает `isEvalSupported: false` как обходной вариант.
- [GHSA-hq66-cqwq-w95j](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j): affected начинается с `5.6.83`, исправление `6.2.108`; описаны выполнение scripting и условия CSP.

Версия 4.10.38 не попадает в указанные уязвимые диапазоны этих двух advisory. В текущем adapter передаётся `isEvalSupported: false`; scripting manager/viewer scripting pipeline не создаётся. В shell CSP `script-src 'self'` и `object-src 'none'`, зависимости грузятся локально; `worker-src 'self' blob:` разрешает локальный module-worker wrapper PDF.js. Наличие параметра `enableScripting: false` в вызове не подменяет факт отсутствия scripting manager: adapter использует API рендеринга, а не полный PDF.js viewer.

Эти факты не являются заключением об отсутствии всех уязвимостей в PDF.js, pdf-lib, fontkit или PDF-парсерах. Полный аудит зависимостей, всех форматов и вредоносных файлов в этом этапе не заявлен.

## Дополнение 6.0.25 — единая настройка поиска

Дополнительное поручение владельца: Google по умолчанию в обычном и приватном режиме, компактный выбор поисковика рядом с полем новой вкладки и видимое текущее название. Реализованы Google, Bing, DuckDuckGo и Яндекс. Кнопка находится рядом с формой поиска и открывает список через существующий modal barrier, который убирает native страницы из-под диалога. В списке выделен текущий пункт; при открытии он получает фокус. Поддержаны стрелки, Home/End, Escape и возврат фокуса на кнопку. Обновление выбранного названия не очищает набранный запрос. Исходники: [start.js](../../desktop/mouse/start.js), [start.css](../../desktop/mouse/start.css), [overlays.js](../../desktop/mouse/overlays.js).

Один [mouse-search.cjs](../../desktop/mouse-search.cjs) нормализует запросы адресной строки и новой вкладки. Настройка обычного режима сохраняется отдельно как `mouseSearch: {engine}`; чистый профиль использует `google`. Валидная существующая настройка сохраняется, включая перенос ранее записанного `quadroStartPage.searchEngine` или `quadroPreferences.searchEngine` в новый ключ. HTTP(S)-адрес не превращается в запрос другого поисковика; привилегированные схемы и URL с credentials отклоняются. В [mouse-library.cjs](../../desktop/mouse-library.cjs) запись поискового запроса требует точного совпадения с сформированным URL известного поисковика, включая origin, path, имя параметра и запрос. Посторонний URL или дополнительные параметры не проходят эту проверку.

При входе в инкогнито создаётся отдельный сервис с текущим значением обычного режима. Private setter меняет только переменную в памяти и не вызывает `store.set`; существующее отключение приватной истории и поисковых записей сохранено. Перезагрузка оболочки в пределах того же приватного сеанса не меняет выбор, а выход и повторный вход наследуют обычную настройку заново. Пример контракта: обычный Bing → новый приватный Bing → приватный DuckDuckGo → выход → следующий приватный Bing. Отдельной постоянной настройки приватного поисковика нет. Интеграция: [mouse-browsing.cjs](../../desktop/mouse-browsing.cjs), [mouse-start.cjs](../../desktop/mouse-start.cjs), [mouse-private.cjs](../../desktop/mouse-private.cjs).

Технический контракт оболочки использует существующий trusted `mouse:start` IPC:

```js
await N.start('get'); // .search = {engine, name, engines: [{id, name}], private}
await N.start('preferences', {searchEngine: 'bing'});
browser.mouseSearch.state();
browser.mouseSearch.resolve(rawInput); // нормализованный URL, строка
```

Локальная проверка [mouse-search.test.cjs](../../desktop/mouse-search.test.cjs): **8 PASS**, включая настоящие start/browsing command wrappers с подставленными native page/image сервисами. Вместе с существующими start/library/private тестами целевой прогон дал **19 PASS, 0 FAIL**. Дополнительный временный DOM QA дал **4 PASS** на фактических `start.js` и `overlays.js`: выбор и фокус, обновление двух новых вкладок без потери текста, отказ записи без ложной смены названия, private RAM/re-entry. jsdom не добавлен в зависимости продукта. Эти проверки входят в локальный checkpoint; native выбор клавишами и реальная геометрия списка пока не подтверждены запуском установленного приложения.

## Итоговый план выпуска — одно обновление 6.0.23 → 6.0.25

Решение владельца на финальной подготовке: объединить все подготовленные функции 6.0.24 и 6.0.25 в один выпуск. Отдельная публикация и промежуточная установка 6.0.24 не требуются. Все её проверки Agent Mouse, сохранения пользовательской сетки, истории раскладок и scoped progress остаются обязательными внутри 6.0.25; старые native facts имеют собственную schema version и не переписываются в 6.0.25.

На 2026-11-18 повторно прочитаны [публичный release 6.0.23](https://github.com/jeep-jim/OSMINOG-Releases/releases/tag/quadro-macos-v6.0.23-arm64), [канал macOS arm64](https://github.com/jeep-jim/OSMINOG-Releases/blob/main/channels/mouse/macos-arm64.json) и [updater по неизменяемому source SHA](https://github.com/jeep-jim/OSMINOG/blob/f3019ed8efae25aac9bad5e3b006ed6b4a9d3954/desktop/mouse-update.cjs):

| Предыдущий выпуск | Проверенное значение |
| --- | --- |
| Публичная версия / release ID | 6.0.23 / `449435220` |
| DMG asset ID / размер | `761489653` / `132165312` байт |
| DMG SHA-256 | `a4165a9c97516836a13d5916377191cb6b3665243400c0d13bed8c44dd88b4fe` |
| Tested source | `f3019ed8efae25aac9bad5e3b006ed6b4a9d3954` |
| Updater Git blob SHA | `c4a9564bc5a7c3cf2c6798b5eade9680ee0e57cf` |
| Updater UTF-8 bytes / SHA-256 | `6250` / `1e5731b944af2415d384771642a2e26070f0f1d19de4069db23a9e8ab7b92252` |

Git blob SHA проверен независимо по формуле SHA-1 от `blob <длина в байтах>\0` и фактических bytes updater, совпал с SHA primary GitHub file response. Известные previous-release значения заполняют только `pin.previous`; они не являются доказательством готовности нового кандидата.

Обязательный upgrade gate: `MOUSE_625_REAL_623_TO_625_REPLACE_RELAUNCH_PROFILE_PASS`, build token `real-623-to-625-profile-preserving-install`. Он требует реального публичного DMG 6.0.23 с совпадающими размером и SHA-256, замены на точный кандидат 6.0.25, повторного запуска и сохранения профиля. После переключения публичного канала настоящий 6.0.23 updater, загруженный как `legacy623-update.cjs` из закреплённого source и проверенный по Git blob, должен анонимно обнаружить 6.0.25 и полностью скачать проверенный установщик. Publisher не заменяет эти операции синтетическим тестом.

В release PR включается `tools/mouse624-release.py` только как неизменённая зависимость 6.0.25 wrapper; отдельные 6.0.24 workflow и staging не активируются. Pins, подтверждение готовности и точные artifacts нового выпуска остаются незаполненными до native/installed приёмки. Исторические результаты промежуточной подготовки 6.0.24 не объявляются её публикацией.

# Mouse Browser 6.0.24 — сохранение сетки и прогресс задач

## Прямое уточнение владельца

После установки 6.0.23 выбор Agent Mouse вместо DeepSeek в правом списке ИИ сбросил пользовательскую сетку. Владелец поручил отделить выбор сервиса от раскладки, добавить историю сеток с возвратом/повтором и выбором сохранённого состояния в заголовке норки, поправить вертикальный стык её основания с футером на один видимый пиксель. Дополнительно поручены нижние «пилюли прогресса» с API для подключённых моделей и внешних агентов.

Работа основана на main `dbc738d10ca29048e1d46de574b4e79d578313f0`. Предыдущий опубликованный выпуск — 6.0.23, его протестированный исходник `f3019ed8efae25aac9bad5e3b006ed6b4a9d3954`. Эти источники не заменяются и не перепаковываются.

## Исправление потери сетки

В 6.0.23 `openAI(mouse://agent)` вызывал `applyMode('agents')`. В 6.0.24 состояние `agentOpen` отделено от `mode`: выбор сервиса меняет правую панель и сохраняет дерево, доли разделителей, соответствие окон вкладкам, порядок, активное окно, ширину ИИ и прежнюю веб-сессию. Готовая сетка «Агенты» применяется только явным выбором режима. Старые сохранения режима agents без поля agentOpen мигрируют с открытой панелью; явное false имеет приоритет.

Обычная сверка живых вкладок теперь только удаляет недействительные ссылки. Она не заполняет свободные окна случайными фоновыми вкладками. Заполнение выполняется при явном создании/разделении сетки. Скрытая веб-панель ИИ при открытом Agent Mouse сохраняется живой, но не выдаётся за видимое окно в счётчике или превью.

## История раскладок

Каждый из пяти столов хранит текущую сетку и до 30 шагов назад/вперёд, дополнительно ограниченных 512 KiB на стол. Сохраняются дерево и пропорции, привязки окон, порядок вкладок, параметры правой панели и режим. Версии имеют устойчивые идентификаторы и время; история переживает перезапуск приложения. Изменения заголовков сайтов, фавиконок, фокуса и один лишь выбор Agent не создают лишние шаги. Жест изменения размеров группируется в один шаг.

В центре заголовка норки находятся «←», «История сетки», «→». Открытый список показывает миниатюры геометрии, дату, число окон и кнопку восстановления. Список загружается по запросу, без периодического опроса или снимков сайтов. Выбор версии выполняется атомарно; ещё не сохранённая пользовательская правка учитывается перед переходом. Undo/Redo проходит через ту же очередь, что сохранение и переключение стола.

История не открывает сайты, не создаёт WebContents и не восстанавливает уже закрытые вкладки. После закрытия или переноса вкладки её ID исключается из всех сохранённых состояний исходного стола. Освободившееся окно остаётся свободным. Восстановление раскладки останавливает активный агентский сеанс перед изменением геометрии.

В 6.0.23 отдельной истории раскладок не было. `desktop/storage.cjs` хранит одну `workspace.json.bak` перед записью, но пользовательский профиль и его резервная копия здесь не предоставлены. Восстановление конкретной уже потерянной сетки не подтверждено. Новая история начинается с состояния, которое доступно при обновлении.

## Контур норки

Верхняя кривая продолжает использовать одно опорное раскрытое состояние. Высота предпросмотра и панели истории не изменяет радиус. Конец SVG-контура выравнивается по фактическому центру верхней границы футера: `footer.top + borderTopWidth / 2`. При границе 1 CSS px это сдвиг на 0,5 CSS px относительно прежней геометрии, то есть один физический пиксель при масштабе 2. Цвет берётся из прежнего `--line`; нижняя граница под самой норкой не рисуется.

## Пилюли прогресса

Отдельная строка высотой 38 px появляется над нижней панелью только при наличии индикаторов. Поэтому нативные страницы не перекрывают кнопки пилюль. Заполнение изменяется CSS transform, без постоянного изменения размеров страниц. Показаны источник, стол, короткое действие и процент. Процент модели отмечен «оценка ИИ»; неизвестный процент отображается без числового значения. Пульсация — оформление ожидания, а не доказательство активности процесса.

Открытая страница или локальная оболочка может вызвать:

```js
await window.MouseAgent.updateProgress(37, 'Пишу код', { taskId: 'draft' });
await window.MouseAgent.updateProgress(null, 'Ожидаю ответ', { taskId: 'draft' });
await window.MouseAgent.updateProgress(100, 'Готово', { taskId: 'draft' });
```

Внешний подключённый агент использует `AgentController.setProgress(percent, statusText, {taskId})` либо расширение CDP-коннектора `browser.setProgress`. Описание находится в `desktop/mouse-agent/PROGRESS.md`. В системную инструкцию worker добавлен вызов этого инструмента для долгих задач. На старте неизвестный процент, явное завершение — 100. Ошибка, лимит шагов, Stop и отсутствие обновлений не объявляются успешным завершением.

Терминал начинает с неопределённого прогресса. Результат определяется реальным кодом завершения команды, а не числом строк stdout. Для команды, запущенной в фоне, подтверждается только её запуск, не окончание фоновой работы.

Публичный page API предоставляет только сообщение о прогрессе. Он не даёт доступ к терминалу, файлам, навигации или другим вкладкам. Main определяет источник, подпись и стол по настоящему отправителю IPC; поля, присланные страницей для подмены владельца, не используются. Подфреймы не получают мост. Закрытие/навигация/перенос страницы очищает старые индикаторы. При приватном режиме и блокировке экрана данные очищаются, новые сообщения страниц отклоняются.

Индикаторы живут только в памяти. Ограничены 12 активных задач, 4 на владельца и 24 кратко сохранённых завершения; события для UI объединяются до 10 раз в секунду. 100% показывается 2,5 секунды и исчезает. Stop/ошибка сохраняют последний процент и показываются 5 секунд. После 30 минут без обновлений отображается «Нет обновлений», без заявления, что работа остановлена. «×» лишь скрывает индикатор; настоящая кнопка Stop Agent вызывает прежний контроллер остановки worker/PTY/CDP.

Обычный веб-чат сам по себе не начинает передавать процент из текста ответа. Нужен явный вызов API со стороны интеграции сайта или подключённого агента. Процент не даёт достоверного времени до завершения.

## Проверки и выпуск

Добавлены отдельные проверки сохранности истории, принадлежности page progress, очистки после навигации/закрытия/переноса, ограничения событий/памяти и завершения сеанса Agent после уничтожения окна. Нативный набор дополняется проверкой реального выбора Agent из пользовательской сетки, сохранения WebContents и документов, Undo/Redo/выбора истории после reload, настоящего page/SDK progress и пикселей стыка в обеих темах.

Кандидат должен пройти существующие проверки установленной arm64-сборки, инкогнито, профиля, CDP/PTY и реальную замену 6.0.23 → 6.0.24. Publisher сохраняет все прежние требования, использует неизменный проверенный пакет и подтверждает обнаружение/полную загрузку новым каналом через настоящий updater 6.0.23. Локальный полный прогон `cd desktop && node --test mouse*.test.cjs`: **231 PASS, 0 FAIL**. Это модульные проверки, не доказательство установленной Mac-сборки. Точные нативные результаты, ссылки и хэши будут записаны после выполнения. До этого кандидат не объявляется опубликованным.

Профиль, App ID, partition, каналы и данные других продуктов не меняются. Измеренное процентное снижение CPU/RAM не заявляется. Статус предварительной ad-hoc arm64-сборки без Developer ID/нотариализации остаётся прежним.

## Две неуспешные попытки e719f4f

Обе попытки [run 44232015927](https://github.com/jeep-jim/OSMINOG/actions/runs/44232015927) выполнялись на одном исходнике `e719f4f3b4950ee78be2aa582cf2c5122307cc15`. Подготовка, модульные проверки и сборка DMG/ZIP прошли. Обе попытки остановились в проверке установленного приложения; шаг привязки и загрузки candidate был пропущен.

**Попытка 1, job 134559089238:** проверка `mouse-609-smoke.cjs` остановилась на `size HUD for both affected panels`: после отправленного перемещения разделителя найдено меньше двух индикаторов размера. Тест использовал прежние интервалы 100 мс после нажатия и 140 мс после перемещения. Точная причина отсутствия индикаторов из журнала не установлена; сбой не объявляется доказанной причиной в продукте или macOS. На предыдущем исходнике `62ab4fb` с тем же рабочим кодом этот сценарий прошёл. Выполнен один повтор того же job без изменения исходника, интервалов и assertions. Проверки 623/624 в первой попытке ещё не выполнялись.

**Попытка 2, job 134560977449:** старый HUD-сценарий прошёл, как и `MOUSE_623_BURROW_GEOMETRY_AND_SEAM_PASS`, `MOUSE_623_TAB_LIFECYCLE_CHIPS_STABILITY_PASS` и проверка Agent entry. Новый `mouse-624-smoke.cjs` остановился в `capturePages`: recorder вызвал `BrowserWorkspace.get()` для внутренней вкладки `mouse://start`. В `mouse-start.cjs` такие вкладки хранятся отдельными записями оболочки без WebContents, поэтому обычный getter отверг запрос. Это ошибка тестового recorder, а не разрешение изменить проверку принадлежности вкладок в продукте.

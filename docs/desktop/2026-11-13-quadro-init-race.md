# Quadro 6.0.1 — проверка восстановления раскладки

В повторном PR run43438975085 проверка read после restart обнаружила сохранённый single-pane default вместо split-дерева. Разбор: renderer подписывался на browser:state/browser:focus до завершения quadro:init; ранняя загрузка восстановленной страницы вызывала reconcile/save со значениями m.tree по умолчанию. Нельзя считать это случайным зелёным/красным тестом и публиковать первый прошедший кандидат.

Исправление: до загрузки preferences никакие save/focus/reconcile не выполняются; browser:state сохраняется как pendingState. После восстановления дерева/слотов разрешается сохранение. Flush при закрытии во время старта не записывает default поверх ещё не прочитанного профиля. В CI добавлено принудительное раннее browser:state и задержка ответа init450ms (только CI=true + абсолютный тестовый профиль + специальный флаг), чтобы проверка восстановления воспроизводила гонку детерминированно.

Первый run43438012311 остановился ещё раньше: тест принимал нативный hide-event при входе macOS в fullscreen за ошибочный вызов hide(). Тест уточнён: запрещён именно вызов win.hide(), а настоящий выход по-прежнему обязан дать leave-full-screen, сохранение, закрытие окна и завершение процесса. Source run43438961565 прошёл, но его байты не публикуются из-за найденной гонки восстановления.

Следующий кандидат должен пройти оба Quadro запуска и release-проверки перед публикацией. История docs/desktop/2026-11-13-quadro-compact.md сохраняется.

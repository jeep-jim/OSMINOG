# 13 ноября 2026 — M1 Pro: закрытие ИИ освобождает всю ширину

Дополнение к OSMINOG_BROWSER_ROADMAP.md и docs/desktop/2026-11-13-macos-arm64.md. Прямое уточнение владельца: после закрытия правой панели ИИ все вкладки должны расширяться до правого края без пустой колонки. M1 Pro подтверждён повторно.

Причина: .body сохраняла три фиксированных grid-track даже при hidden на обеих sidepanel. Mac-стиль теперь выводит две колонки при отсутствии видимой боковой панели. При открытии ИИ/кошелька исходная правая колонка возвращается; мобильное правило до 820px не переопределяется. Существующие обработчики renderAI/renderWallet вызывают requestLayout для настоящих WebContentsView. Дополнительный resize после вставки Mac CSS синхронизирует первое отображение.

Это отдельный Mac 5.0.3. Версия и исходники Windows, его feed, Android, Chrome, АвтоЦена не меняются. База main9f7c9743229926309370ba00dd6516038ad3e555.

Регрессионный тест запускается внутри упакованного Mac-приложения: 1/2/4/6 настоящих вкладок при ширине1440/1100/900, закрытие крестиком и кнопкой AI, повторное открытие, точные native bounds до правого края, сохранность webContents и содержимого страниц без reload, сохранение колонки открытого кошелька. В этом коммите тесты подготовлены; результаты и публикация фиксируются отдельно только после фактического успеха.

Предыдущая Mac5.0.2 прошла source runs43398398474/43398409996, а release run43398829975 прошёл установку из DMG, но публикация остановилась на HTTP404 при чтении ещё чернового релиза по тегу. Не выдавать эту сборку за опубликованную. Для5.0.3 проверять черновой release по его числовому ID, сверять удалённые SHA-256 и лишь затем открывать публикацию. Старый черновик не перезаписывать.

Ограничения сохраняются: подпись ad-hoc, без Developer ID/notarization, ручное обновление. CI не равен запуску на Mac владельца и не подтверждает авторизацию в сторонних сервисах.

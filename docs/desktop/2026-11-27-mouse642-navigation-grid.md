# Mouse 6.0.42 — переходы внутри сайта и возврат в сетку

## Поручение владельца и границы

27.11.2026 владелец подтвердил публикацию исправления в порядке **macOS → Linux → Windows**. Источник — [PR222](https://github.com/jeep-jim/OSMINOG/pull/222). Отдельная версия 6.0.42 нужна для неизменяемых установщиков и обнаружения обновления уже установленной 6.0.41. Старые опубликованные файлы, App ID, профиль, partition, cookies и адреса каналов сохраняются.

Два изменения поведения:

1. Обычный переход по разделам текущего сайта остаётся в существующей вкладке и её WebContents. Совпадающий hostname и его родительские/дочерние поддомены считаются одним сайтом независимо от схемы и порта. Внешняя ссылка открывается в новой обычной вкладке. То же правило действует для `target=_blank`, `window.open` и навигации бокового ИИ-сайта.
2. Угловая кнопка «−» в классическом виде вызывает существующий `returnToGrid()` и возвращает сохранённую сетку. В режиме сетки она по-прежнему сворачивает окно средствами ОС. Страницы, расположение панелей и вкладка в верхней полосе сохраняются.

## Проверяемые доказательства

Unit-контракты покрывают границы hostname, обработчики самого сайта, внешние переходы, боковую ИИ-панель и обе ветви кнопки «−». Установленный workspace-suite выполняет настоящий щелчок ОС по внутренней ссылке, проверяет неизменные ID вкладки/WebContents и набор вкладок; внешние ссылки проверяются отдельным hostname `localhost` относительно `127.0.0.1`. Независимый Python-reader проверяет native receipts и снимки.

Существующие retained-suite используют разные hostname для действительно внешних переходов. Fixture загрузок допускает только два локальных hostname и по-прежнему требует точное совпадение фактического origin страницы с origin принадлежащего тесту HTTP-сервера.

В финальном Windows nativePages найден ещё один прежний fixture: ссылка `/second` внутри текущего сайта ожидалась как новая вкладка. При новой семантике она меняла исходный документ вместе с его наблюдателем pointerdown. Внешний сценарий Windows переводится на отдельный hostname `localhost`; проверка истории через адресную строку и исходный `127.0.0.1` сохраняется. Linux на промежуточном `1facb16c` прошёл полный source workflow45941526055 с Ubuntu24.04 и независимый offline publisher-reader; его пакеты не переносятся на новый source SHA.

Первый полный [Mac run45939841057](https://github.com/jeep-jim/OSMINOG/actions/runs/45939841057) на `4fcf631fa42281eac6b520667a11fc18abe1e48c` остановился в независимой проверке цветной иконки настроек: тёмный overview содержал старый native-кадр страницы поверх уже открытого диалога. DOM-ready и два renderer-frame не подтверждали обновление OS capture. Для снимков настроек добавлена проверка совпадения выбранного неподвижного участка интерфейса с текущим shell-frame внутри прежнего ограниченного capture-loop. Отброшенные попытки сохраняются; итоговая независимая проверка PNG не ослабляется.

## Выпуск

**Статус этой записи: кандидат готовится; публикация 6.0.42 ещё не подтверждена.**

Требуются успешные нативные сборки точного нового source SHA: Mac arm64, Linux x64 с Ubuntu 24.04 и Windows x64 с modern Windows gate. Проверяется обновление реальных опубликованных пакетов 6.0.41 → 6.0.42, сохранены отдельные legacy629-проверки. Publisher 642 создаётся отдельными файлами в собственном [OSMINOG-Releases](https://github.com/jeep-jim/OSMINOG-Releases); его pins должны содержать фактические source/merge/run/job/artifact, размеры и SHA256.

Каждая платформа проходит повторную установку и независимую приёмку перед публикацией и переключением своего feed. Следующая платформа допускается после проверки полного публичного файла предыдущей. После выпуска отдельно проверяются каталог `https://mouse.black/downloads.json`, прямые HTTPS-загрузки, HEAD/Range, полные размеры/SHA256 и канал обновления. Точные итоговые ссылки добавляются после фактического завершения; готовность по одному коммиту или сборке не заявляется.

# Mouse Browser 6.0.36 — производительность, удаление плиточного поиска, настройки в панели

## Последнее решение владельца

21 ноября 2026 пользователь сообщил, что плиточный поиск неудобен, сетка и переключение столов подвисают даже на Mac Pro. Поручено полностью убрать собственный поиск из проекта, сфокусироваться на плавности, обновить сразу macOS arm64, Windows x64 и Linux x64. Настройки агента должны открываться в его текущей панели, без popup. Это заменяет прежние решения SearXNG/YaCy, преобразования выдачи выбранной системы в плитки и macOS-only выпуска. Разрешение на реализацию и публикацию дано явно.

## Исходное состояние и выявленные затраты

Исходная ветка начата от main `fe7681e4e2fbaa1ac1e879894442c1f70d585133`; репозиторий публикации — от `961c05df5a15a774876720b5ef234659b1040e27`. Последний опубликованный Mac — 6.0.35, Windows/Linux — 6.0.34. Профиль, App ID, partitions, cookies и работающие адреса каналов сохраняются.

В прежнем обычном переключении сначала снимались изображения старого и нового столов, затем выполнялась анимация 330 мс. В фактическом свежем publisher 6.0.35 (`44898480279`) отчёт `mouse-631-stress.json` при 50 страницах и пяти столах зарегистрировал 10 переключений: медиана 592.180083 мс, p95 628.077833 мс, максимум 649.285916 мс. Это историческое измерение на CI, не измерение Mac Pro владельца и не доказательство ускорения новой версии.

## Изменения рабочего кода

- Удалены плиточная поисковая панель, её preload/IPC, скрытые поисковые views, транспорт, извлечение DOM, анализ выдачи, старые поисковые зависимости и deployment workflow/infra этого компонента. Исторические журналы и уже выпущенные пакеты остаются. Удаление исходников инфраструктуры не утверждает выключение удалённого сервера. Обычная навигация и выбранный поисковик в адресной строке браузера сохраняются.
- Обычное переключение размещает уже существующие живые страницы; не снимает и не декодирует изображения, не клонирует DOM/CSS и не ждёт декоративной анимации. Проверка представления живой сетки остаётся. Выбор стола в меню немедленно закрывает меню перед переключением, без ожидания декоративного закрытия. Открытая Норка сохраняет своё пиксельное удержание и отдельный анимированный маршрут при переключении её фона.
- Сохранение столов отделено от визуального переключения. Очередь объединяет ещё не начатые промежуточные записи, сохраняет последнее состояние, сообщает об ошибках и ждёт записи при flush.
- Обновления title/favicon фонового стола объединяются в окно 250 мс; события видимого стола получают короткое окно 16 мс. Команды пользователя не задерживаются этой очередью.
- Декорация активной вкладки пересчитывается один раз на кадр, не провоцирует немедленный layout из MutationObserver и не перезаписывает неизменившуюся геометрию. Повторный выбор уже активного окна не перестраивает сетку.
- Настройки Agent Mouse представлены внутренней страницей панели с возвратом в чат. Сохраняются черновик, выделение, прокрутка и узлы переписки; поток ответа продолжает поступать при открытых настройках. Остановка и запрос разрешения доступны в этой же панели. Настройки не открывают dialog и не блокируют native-страницы.

## Приёмка

Локально пройдены 102 целевые проверки сохранения столов, переключения, previews и surface ownership; отдельные 11 проверок сравнения производительности отвергают некорректные замеры, подменённые сводки, перезагрузку документов, capture при переключении и отсутствие улучшения. Это не заменяет установленные проверки.

Для каждой платформы запускается точный опубликованный прежний пакет в отдельном профиле с его неизменённым `--mouse-631-smoke`, затем кандидат на том же runner. Сохраняются исходные JSON, реальные OS-кадры, hash пакета/исполняемого файла, PID, исходники и идентификатор job. Сравниваются одинаковые сценарии: 20 и 50 страниц, пять столов, реальные локальные HTTP-потоки и обновления metadata. Процентили пересчитываются из исходных задержек по формуле `sorted[floor((count - 1) * quantile)]`.

Критерии для кандидата: медиана ниже прежней в обоих сценариях; при 50 страницах p95 не более 250 мс, максимум не более 600 мс; ноль native image capture на обычное переключение. Проверяются сохранение webContents/document identity, формы/scroll/cookies, единственная загрузка каждой страницы, живые потоки, реальные пиксели и отсутствие renderer crash. Сырые промежутки кадров и main loop в 6.0.36 сохраняются. Старый пакет их полностью не записывал, поэтому его старые сводки не выдаются за заново рассчитанные.

Отдельные установленные сценарии проверяют отсутствие плиточного поиска в UI/preload/IPC/пакете/hidden views, обычную адресную строку, inline Agent settings в обеих темах при ширине 300/400 px, реальные native clicks, библиотеку файлов, закрепление окон, прежние регрессии и обновление профиля. Локальная модель в Agent smoke — тестовый HTTP/SSE endpoint; доступ к личному Ollama владельца не заявляется.

## Публикация

На момент подготовки этого журнала 6.0.36 не опубликована. Три платформы должны получить полный комплект exact package pins с общим source/sourceMerge прежде, чем разрешится любой publisher. Каждый publisher повторно устанавливает и проверяет свои точные пакеты, затем проверяет анонимный канал обновления. Готовность трёх платформ не означает атомарность трёх независимых GitHub upload jobs. Фактические ссылки, SHA и результаты будут дописаны после проверок.

Mac остаётся предварительной ad-hoc сборкой без Developer ID/нотариализации. Проверки на CI не объявляются проверкой физического Mac Pro владельца.

### Исправление кодировки Windows publisher

Первый фактический [Windows publisher 44917016603](https://github.com/jeep-jim/OSMINOG-Releases/actions/runs/44917016603/job/136884784676) остановился до импорта EXE: общий all-platform preflight пытался прочитать русские Mac release notes через `Path.read_text()` с Windows default cp1252 и получил `UnicodeDecodeError` на байте `0x81`, позиция 73. Публикация и смена Windows-канала в этом запуске не выполнялись.

В [release commit baeff8ac7dcde75e7af8d6e4b0795e1b91c78c6b](https://github.com/jeep-jim/OSMINOG-Releases/commit/baeff8ac7dcde75e7af8d6e4b0795e1b91c78c6b) четыре чтения новых файлов 6.0.36 получили явную UTF-8; Windows publish job получил `PYTHONUTF8=1`, чтобы retained readers Linux notes и дочерние Python процессы также использовали UTF-8.

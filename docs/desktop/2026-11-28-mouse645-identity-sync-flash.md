## Поведение продукта

Обычный браузер работает без регистрации. Mouse ID связывает устройства: имя, фото, числовой ID, пароль и код восстановления. ID 1 зарезервирован владельцу; регистрация требует отдельного одноразового bootstrap, который находится только на собственном сервере. Остальные ID начинаются с 2. Имя/аватар сами по себе не являются доказательством личности.

После входа на другом устройстве восстанавливаются разрешённые настройки: сетки до 12 окон с отдельной AI-панелью, рабочие столы, обычные адреса вкладок, закладки, тема, оформление, размеры панелей и разрешённые переключатели. Схема ограничена 2 MiB. Файлы, снимки, захваченный текст, история, загрузки, cookies и пароли сайтов не включаются. Известные авторизационные и подписанные URL исключаются и остаются локальными.

Каждые 30 секунд авторизованное устройство проверяет маленький номер revision; полный state скачивается при изменении. Запись использует CAS и слияние относительно предыдущего состояния. Конкурентные закладки сохраняются; конфликтующие сетки сохраняются отдельными вариантами. Изменения без интернета остаются на диске. Во время работы чужое изменение не закрывает текущую форму: оно применяется после явного действия или перезапуска.

У аккаунтов отдельные каталоги Chromium и настроек. Проверка доступа выполняется до создания страниц. Выход удаляет сохранённую сессию, отзывает её на сервере при доступной сети и выбирает нового чистого гостя. Перед этим выполняется ограниченная по времени последняя синхронизация настроек. Исходные данные и прежние каталоги сохраняются, но следующий пользователь их не получает через интерфейс.

Flash открывается молнией рядом с существующими боковыми панелями. Получатель видит подписанное имя/фото/ID отправителя и подтверждает приём. Сервер передаёт ограниченные служебные сообщения и знакомит устройства; payload идёт по прямому RTCDataChannel. Файлы не загружаются в серверное хранилище. Закрытие панели не обрывает передачу; выход из аккаунта и переход в private прекращают доступ к ней.

Лимит бесплатной передачи — 100000000000 байт по manifest, включая возобновляемую сессию без повторного подсчёта чанков. Биллинг, entitlement платного безлимита и 18 столов в 45 не реализованы.

Версия и проверка обновления находятся внизу настроек. Нижняя кнопка появляется только при доступном обновлении/загрузке/готовой установке. Отображаемое имя установленного приложения — Mouse; внутренние имена bundle/executable и канал обновления сохраняют совместимость с 44.

## Код и проверка

- `desktop/mouse-account-client.cjs`, `mouse-account-proof.cjs`: pinned issuer, signed device binding, protected native credentials, refresh/recovery/logout.
- `desktop/mouse-profile-context.cjs`: изолированные аккаунты и новые поколения гостя, durable selector, миграция исходного профиля без удаления.
- `desktop/mouse-sync-schema.cjs`, `mouse-config-sync.cjs`: строгая схема, export/import, CAS, offline/conflict merge, account/epoch guards.
- `desktop/mouse-flash*.cjs`, `mouse/flash/`: grants, bounded streaming, encrypted rendezvous, checkpoints и durable completion receipt при потере последнего ACK.
- `services/mouse-identity/`: Node SQLite/WAL, password scrypt, session revocation, recovery, metadata and sealed invitations.
- `desktop/mouse-645-account-smoke.cjs` и `tools/mouse-645-account-verify.cjs`: установленный executable, независимое наблюдение PID, реальные HTTP/SQLite и OS storage, A/B/guest, второй профиль устройства, logout без ручного sync, pre-window guard.
- `desktop/mouse-645-smoke.cjs`, `tools/mouse-645-verify.py`: нативный ввод и проверяемые изображения UI, sidebar/overlay barrier, updater visibility, appearance/restart. Все прежние Mac gates сохраняются.

## Собственный сервер

[Deploy 46127013296](https://github.com/jeep-jim/OSMINOG/actions/runs/46127013296), source `e274e20419962ce108f59ba0b3638b0635b43fd9`: отдельный `osminog`, `/opt/osminog/mouse-services`, Node v24.22.3, подписывающий ключ и SQLite вне Git. Релизы кода переключаются атомарно, данные и issuer сохраняются между ними.

| Сервис | Адрес | MemoryMax | CPUQuota |
|---|---|---:|---:|
| Identity | loopback TCP 8788 | 256 MiB | 25% |
| Rendezvous | loopback TCP 8787 | 128 MiB | 15% |
| STUN | UDP 3478 | 96 MiB | 10% |

Лимиты HTTP/body/очередей/connections и дорогих password операций ограничивают нагрузку. Отключение signaling после прямого соединения не проксирует payload. Это общая VM с ограниченными процессами, а не отдельное физическое оборудование. [Read-only public probe](../../../infra/mouse-services/public-probe.py) проверяет website, pinned issuer, broker route и UDP STUN без создания аккаунтов/комнат.

### Оставшееся подключение HTTPS

Own-user deploy не может менять root-owned `/etc/nginx/conf.d/mouse.black.conf`. Старые административные исключения закрыты; чужие ключи/сервисы не использовались. Подготовленный `infra/mouse-services/configure-https.py` добавляет только `/v1/accounts/` и `/v1/rooms` в существующий Mouse vhost, с rate/body/time limits, перезаписью trusted-proxy заголовков, отключённым access log и `nginx -t` до/после. При ошибке проверки возвращает исходный файл. Автоматический deploy не запускает этот скрипт.

Проверенный SHA256 исходного vhost: `29a0aa79051a08d854c66c5422d7381f2213fca42f2c3fc6dc9da7ff8b69c65e`.

SHA256 подготовленного скрипта: `ebd8e032a9f62adb303d6c16929b6244e1394d74c216de62097d5dc8ef90b4fc`.

Одна операция администратора: скопировать подготовленный скрипт в свой root-owned каталог, проверить SHA256 копии и применить с `--expected-sha256` выше. Если vhost уже изменился, скрипт остановится; нужно перечитать конфигурацию, а не обходить проверку. После применения обязателен `public-probe.py --require-ready` и реальная регистрация/передача до изменения канала обновления.

## Материальные пределы

Без TURN некоторые NAT/firewall комбинации не соединятся. Реальная скорость ограничена каналами и дисками двух устройств. Приём сейчас требует hard links; неподдерживаемая файловая система отклоняется до payload. Для первого теста использовать внутренние диски Mac.

Touch ID реализован через защищённый Keychain ACL с проверкой доступности. Текущий ad-hoc пакет без entitlement не имеет такого доступа; пароль/код восстановления остаются рабочим способом входа. Реальная биометрия, почтовое восстановление, две физические машины, WAN и терабайтный объём ещё не подтверждены. Не отключать защиту macOS и sandbox. Windows/Linux остаются опубликованными 6.0.42.

## Однократная настройка владельцем/администратором

На REG-сервере 151.248.113.177 подготовить отдельную непривилегированную учётную запись `osminog` (или `osminog-deploy`), собственный SSH-ключ только для неё и отдельный каталог `/opt/osminog`. Не добавлять аккаунт в sudo/docker группы и не использовать root, ключи, окружения или базы других приложений. Публичную часть нового ключа добавить в authorized_keys только этого аккаунта. Закрытую часть хранить как GitHub Actions secret `OSMINOG_REG_SSH_KEY` в репозитории `jeep-jim/OSMINOG`, environment `osminog-reg`. При имени, отличном от `osminog`, задать там variable `OSMINOG_REG_SSH_USER`.

Секрет вводится непосредственно в GitHub Settings → Environments → osminog-reg → Environment secrets. Не отправлять приватный ключ в переписку, pull request, исходники или журнал Actions. Если учётная запись/ключ ещё не созданы на сервере, один пустой или произвольный secret проблему не решит.

Проверка закрепляет публичную идентичность SSH-хоста. Если REG показывает другой host key, сначала проверить причину и новый fingerprint через доверенную консоль; не отключать StrictHostKeyChecking и не принимать ключ автоматически.

После настройки выполнить `OSMINOG REG — isolated access check` из OSMINOG. Успех означает только разрешённое подключение и чтение ресурсов/состояния выделенного каталога, не готовый deploy. Для установки нужен отдельно подготовленный ограниченный механизм управления только OSMINOG; эта проверка намеренно не выдаёт обычному SSH-пользователю контроль над всеми контейнерами сервера.

До этого домен не переключается и подписанный APK не публикуется. Наличие этого файла не подтверждает создание аккаунта, ключа, каталога или установленного сервиса.

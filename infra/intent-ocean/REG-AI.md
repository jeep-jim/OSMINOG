# Внутренний интеллект OSMINOG через REG — 2026-11-08

Владелец прямо разрешил использовать выделенную на скриншоте **Qwen 3.8 Flash Next**
из ИИ-платформы REG как внутренний интеллект океана. Это обновляет прежний запрет
подключать платные модели именно для этого ограниченного сценария, но не разрешает
покупку GPU, переход на иные модели, внешние чаты или передачу всей переписки.
Модель работает у провайдера; её веса на нашу VM не устанавливаются.

## Состояние: код подготовлен, живое подключение ещё НЕ проверено

В карточке показаны 30 ₽ / 1 млн входных и 90 ₽ / 1 млн выходных токенов.
Это сведения со скриншота владельца, не автоматически проверяемый тариф API.
Пример при 1000 входных и 200 выходных: 1000 × 30 / 1 000 000 +
200 × 90 / 1 000 000 = 0,048 ₽. Это условный запрос, а не измеренная средняя
стоимость магнита. Сравнение нескольких намерений имеет больший вход.

Скриншоты не содержат точного API base URL и поля `model`; отображаемое имя
не заменяет идентификатор. Публичный поиск не дал подтверждённых значений REG.
Поэтому URL и model не угадываются и не подставляются из Alibaba/Vercel.
Ключа модели или SSH-доступа из других проектов здесь нет.

## Как включается

1. REG → ИИ-модели → Qwen 3.8 Flash Next → «Инструкция для API».
   Подтвердить base_url, model, Bearer-авторизацию, Chat Completions и поддержку
   ограничения max_tokens. Параметры подключения можно передать разработчику
   без секретов; сам ключ нельзя присылать в чат или Git.
2. Создать отдельный ключ **ИИ-платформы** для OSMINOG через кнопку «Создать API-ключ»
   на странице моделей. Не использовать управленческий токен REG для серверов,
   root-пароль или ключ другого проекта.
3. Хранить в собственном environment `osminog-reg` репозитория OSMINOG:
   secret `OSMINOG_REG_AI_API_KEY`; variables `OSMINOG_REG_AI_BASE_URL`,
   `OSMINOG_REG_AI_HOST`, `OSMINOG_REG_AI_MODEL`. Сохранение в GitHub само по себе
   НЕ доставляет конфигурацию приложению и не подключает API.
4. После отдельного SSH-доступа и установки проверенного сервиса администратор
   доставляет ключ непосредственно в `/opt/osminog/secrets/reg-ai.key`, доступный
   только процессу OSMINOG и администратору. Не печатать его в CI-логах.
   `compose.reg-ai.yaml` — явное дополнение к основному compose. Оно монтирует
   ключ read-only в `/run/secrets/osminog_reg_ai_api_key`; это не операция деплоя.
5. Проверить один синтетический запрос, затем настоящий магнит с явным согласием
   двух тестовых участников. Сверить `usage`, тариф, ограничения и реальное списание.
   Только после этого считать модель подключённой и оценивать качество подбора.

Разрешены только HTTPS и закреплённое точное имя узла под reg.ru/reg.cloud.
Если инструкция REG использует другой домен, сначала проверить принадлежность,
затем отдельно изменить проверку. Не ослаблять её автоматическим wildcard.
Перенаправления и прокси из среды отключены. Внешние ссылки намерений не скачиваются.

## Работа и границы приватности

- В звезде/профиле есть отдельное согласие на обработку REG текстов собственных
  активных намерений, опубликованных «В океан». По умолчанию выключено, в том
  числе у существующих аккаунтов после миграции. Согласие можно отозвать.
- Черновик, «Только мне», личная беседа, фото/файл/кадр и имена/профили участников
  модели не передаются. Камера остаётся вложением для людей, не видеопотоком ИИ.
- Список кандидатов отфильтрован по доступу, блокировке, актуальности и согласию
  владельцев до отправки. Модель видит текст/тип и временные номера, не user IDs.
  Распространённые URL, телефоны и email удаляются перед отправкой; это НЕ гарантия
  полной анонимности текста, содержащего персональные сведения.
- ИИ ранжирует ограниченную порцию до 24 кандидатов, включая часть свежих намерений
  без общих слов. Это ещё не полнота семантического поиска по всему океану.
- Принимается только проверенный JSON с номерами из переданного списка. Нельзя
  создать человека/намерение/сообщение ответом модели. Объяснение и интерфейсные
  подписи формирует наш код, а не свободный ответ ИИ.
- Перед выдачей результата права, срок и согласия перепроверяются. Отзыв согласия
  прекращает новые обращения и выдачу результатов, но не отзывает уже переданный
  провайдеру запрос. Не обещать E2EE или собственное исполнение весов модели.
- Модель не вызывается при наборе, публикации, открытии профиля или получении
  личного сообщения. Только нажатие магнита порождает CSRF-защищённый POST.
  GET всегда остаётся бесплатным локальным подбором по словам.

## Огграничители пилота

Один одновременный вызов; не более 10 запросов в минуту и 100 за UTC-сутки.
Счётчик сохраняется в отдельной SQLite-базе рядом с БД приложения и переживает
перезапуск. Повторы и переключение на другой платный провайдер отсутствуют.
Кеш результата — 120 секунд, максимум 128 записей, только в памяти.
Входной JSON максимум 18 000 байт, выход ограничен 512 токенами. После сбоя пауза
30 секунд. Лог хранит время/статус/usage, не ключи или тексты.
Это лимиты обращений, НЕ гарантированный денежный потолок: реальную тарификацию
и учёт reasoning-токенов сначала проверяем у REG.

Сетевой вызов вынесен из общей блокировки БД. Ошибка, таймаут, отсутствие ключа,
лимит или занятость оставляют явно обозначенный лексический подбор, не ломая чат.
`configured` означает только наличие корректной конфигурации, НЕ успешную связь.

## Что ещё не решено

Собственный SSH OSMINOG, размещение сервиса, HTTPS и домен, живой API-вызов REG,
подтверждение возможностей именно выбранного размещения Qwen, качество на русском,
реальные затраты, миграция подписанного APK и две реальные мобилки. Эти ограничения
не снимаются наличием модели в каталоге или зелёными контрактными тестами.

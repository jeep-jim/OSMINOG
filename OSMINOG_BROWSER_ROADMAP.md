## Решения владельца — 13 октября 2026

- OSMINOG позиционируется как самостоятельный локальный браузер. Первый этап — Windows; далее другие настольные системы, затем мобильные.
- Ограничения расширения не определяют архитектуру. Разработка расширения не является обязательной частью этого этапа; существующую установку и её данные не удалять.
- Настоящие сайты во вкладках, 1/2/4 изменяемые области, быстрый переход на существующий холст. Холст остаётся общим контейнером проекта.
- Выбранный ИИ — внутри приложения. Контекст страниц/холста и результаты должны проходить полный проверяемый цикл. Открытое окно ИИ само по себе не означает подключение.
- Рендеринг и хранение проекта — на устройстве. Нет серверного браузера, прокси или хранения пользовательских досок на сервере OSMINOG. Авторизация на сайтах и запросы к выбранному облачному ИИ по природе обращаются к этим сервисам.
- Обновление Windows — по кнопке: проверить, скачать, проверить пакет, сохранить текущий проект, установить и перезапустить. Не требовать повторного ручного скачивания каждого выпуска.
- Записывать решения, дефекты, изменения, проверку, опубликованную версию и следующий шаг. Не выдавать планы и тестовые имитации за работу на ПК владельца.

Скриншот 16:47 показывает 4.0.2 и фактический отказ «Действие выходит за пределы вкладки»: видимый ответ DeepSeek использует x=1048/1097 при узкой вкладке. Получение свежего snapshot ПОСЛЕ готового ответа не исправляло старые координаты.

Изменения 4.0.3:
- Вместо наблюдения JSON видимого ответа команда пользователя запускает отдельный служебный цикл выбранного провайдера с BrowserContext, инструментами и обратной связью (до 16 шагов). Обычное сообщение сайта не изменяется и не дублируется; контекст/снимки/результаты туда не отправляются.
- browser_act принимает только token, полученный исполнителем этой задачи и уже переданный модели. Чтение+действие одним ответом, старые токены, смена проекта и Stop блокируют выполнение. Ошибка возвращается модели для нового чтения.
- Правки локального холста применяются через существующий проверяемый executor с project/revision. Виджеты используют существующий sandbox; список инструментов явно ограничен, owner/source полномочия не расширены.
- Подключение учитывает обычную открытую вкладку DeepSeek. Служебные DOM-сессии скрыты из пользовательских вкладок, не переключают активного ИИ, не сохраняются и закрываются после задачи.
- При ошибке сессионного API подключение пробует отдельную управляемую служебную сессию. Оригинальный composer не используется как резервный транспорт.
- Полный BrowserContext остаётся локальным: для автоматического исполнения передаётся краткий индекс вкладок/доски, подробности читаются инструментами. История хранит краткие итоги шагов, а не повторные полные DOM/снимки.
- Проверки: 68 unit-тестов; Windows fixture подтвердил обычный Enter → ввод → чтение → смену темы → чтение → создание красного круга, при единственном исходном сообщении и без дополнительных подтверждений. Сценарий повторён в установленном приложении. Сохранены проверки PDF/DOCX/XLSX и копирования оригинальных файлов через Ctrl+C/Ctrl+V.

Ограничения: видимый ответ сайта и служебное выполнение — разные потоки. Служебный исполнитель получает текущую задачу и живой контекст, но не всю старую переписку сайта. Результат показывается строкой состояния Осьминога. Сессии реальных аккаунтов и реальная Figma пользователя здесь не проверены; fixture не является такой проверкой. Публикация подтверждена проверками ниже.

## 2026-10-15 — исправление маршрута отправки из панели ИИ

На скриншоте Windows 4.0.3 DeepSeek показывает `Server is temporarily unavailable`; причина отказа сервиса на устройстве пользователя не установлена. Отдельно найдена ошибка хоста: обработчик page:user-send допускал только browser.tabs, пропуская видимые диалоги browser.providers. Теперь оба вида пользовательских вкладок доходят до исполнителя; скрытые ephemeral-сессии, чужой проект и удалённые вкладки отклоняются до чтения контекста. Проверка главного фрейма и источника IPC сохранена.

12 целевых unit-тестов успешны, включая новую регрессию панели провайдера и запрет рекурсии служебных сессий. Добавлен Windows smoke с настоящим Enter в панели ИИ. Его CI, установка новой Windows-версии и живой DeepSeek ещё не проверены; это не запись об устранении ошибки сервера провайдера.

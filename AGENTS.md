## Работа и запись результата

Перед работой сверять свежий main. Работать в порученном объёме; документационные изменения и ежедневная сверка roadmap сами по себе не разрешают deploy. Не покупать мощности, не менять DNS, доступы, секреты или другие проекты лишь из-за упоминания домена. Приватные материалы, ключи подписи и токены не писать в Git, логи и отчёты.

Сохранять пользовательские данные и чужие незавершённые изменения. При параллельных записях использовать свежий blob SHA / expected parent; конфликт перечитать, сохранить обе истории, проверить записанное чтением. Коммит или синтетический тест не доказывает установленную проверку и публикацию.

**Mouse:** текущие решения, exact SHA/run, проверка, ограничение и следующий шаг — в `MOUSE_BROWSER_ROADMAP.md` (≤8000 UTF-8 байт; проверять размер). Подробности — по ссылке в задаче/CI. Не накапливать журнал и дубли в старых roadmaps; история — в Git, прежний root AGENTS — в архиве выше (поручения 23 и 28.11.2026).

**Другие направления:** после содержательного шага дополнять свой журнал решениями, изменениями, проверками/ссылками, публикацией, ограничением и следующим шагом. Историю не заменять новым документом; исключение Mouse на неё не распространяется.

## Изоляция инфраструктуры

- Исходники, тесты, серверные проверки, сборки и публикации OSMINOG/Mouse — только `jeep-jim/OSMINOG`; собственный канал выпусков — `jeep-jim/OSMINOG-Releases`.
- Не создавать/запускать workflows OSMINOG в `jeep-jim/AvtoCena`, не использовать её secrets, журнал, runtime, базу или файлы; не направлять владельца в её Actions. Недоступность собственного доступа — блокер, не разрешение обходить границу.
- Общая REG VM разрешена при отдельных ограниченных доступах, каталоге, runtime, данных, файловом хранилище, конфигурации и лимитах. Постоянная автоматизация — пользователь `osminog`, свой `/opt/osminog`, без root/sudo/docker и без изменения сервисов АвтоЦены. Общие CPU/RAM/диск остаются общим риском; это не аппаратная изоляция.
- Разовые административные исключения **закрыты**: [bootstrap собственного доступа](docs/mobile/2026-11-09-vision-0212.md), [подключение mouse.black](docs/website/2026-11-22-mouse-black-launch.md). Они не разрешают повторное использование АвтоЦены. Не извлекать/копировать её ключи, не сбрасывать пароль общего сервера и не генерировать новую пару без конкретной причины.
- Собственные SSH/API-доступы уже проверялись; не просить их повторно без новой проверки, выявившей проблему. REG API и SSH — разные доступы. Параметры модели в `config/reg-ai.json`; значения secrets не читать/не печатать. Синтетический ответ модели не подтверждает deploy или подключение клиента.

## Перед работой над мобильным продуктом

Обязательно учитывать [UI/личные пузыри](docs/mobile/2026-11-08-personal-menu-and-bubbles.md), [REG-интеллект](docs/mobile/2026-11-08-reg-intelligence-verification.md), [персонаж/зрение](docs/mobile/2026-11-09-character-0213.md), [общий океан](docs/mobile/2026-11-09-shared-ocean-0214.md). Эти подробности не нужны для задач Mouse.

Личная отправка не публикует намерение; публичный выпуск — только с явным подтверждением. Не публиковать автоматически личные чаты/камеру/вложения/архивы/черновики. Fixtures обозначать, проверки доступа делать на сервере. ИИ — после согласия, кадр один на отправку, без фонового видео; ключ модели только на сервере. REG разрешён только для согласованного сценария, не для чужих веб-чатов/GPU/бесконтрольной передачи данных. Публичная БД хранит контент; не обещать обратное или нереализованное восстановление аккаунта.

Перед Android-релизом сохранять package/signature и проверять обновление без потери данных. Android TLS не подтверждает запуск Web/PWA; перед ротацией нужен совместимый APK. Не придумывать несогласованные страницы и не смешивать продукты.
